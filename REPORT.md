# Постобработка OCR паспорта РФ

## 1. Приоритет решения

Основная цель - не принимать документы с ошибками, даже ценой большого числа отказов. Итоговый строгий вариант на всей доступной разметке принимает 45 документов из 3000, все 10 полей каждого из них совпадают с разметкой. Ошибочных принятий и календарно недействительных принятых паспортов на этой проверке нет. Для test сформированы 2000 ответов: 45 accept и 1955 reject.

**Прогноз для test: 45 принятых документов, 0 ошибочных.** Число принятых уже известно из запуска. Ноль ошибок - эмпирический точечный прогноз по доступной разметке, а не подтверждённый результат на test: разметка test отсутствует. Покрытие test составляет 2,25%.

## 2. Алгоритм

Решение написано на Python 3.9+ и использует только стандартную библиотеку. Работает на CPU, без сети, обученных весов и доступа к train_labels.jsonl во время обработки. Порядок ответов совпадает с порядком входных документов. У accept выдаются все 10 полей; у reject поля не выдаются.

1. Строки каждого визуального поля сортируются по координатам. Проверяются пропуски строк по верхнему/нижнему отступу и межстрочным промежуткам относительно высоты строки. Размер массива char_conf должен совпадать с длиной исходной строки. Нормализуются регистр и повторные пробелы; точки, дефисы и буква Ё сохраняются.

2. Для каждого символа во всех 10 визуальных полях и обеих строках MRZ требуется char_conf не ниже 0,99. Низкая уверенность даже в числовом поле, совпадающем с MRZ, приводит к отказу. Проверяются наличие, длина и диапазон оценок MRZ. Средняя уверенность по полю не заменяет посимвольную проверку.

3. Из визуальных значений строятся обе ожидаемые строки MRZ. Используются кодировка «модернизированный клер», перенос четвёртой цифры серии в дополнительную область, контрольные цифры с весами 7/3/1 и итоговая контрольная цифра. Требуется полное совпадение строк. Неизвестные значения не восстанавливаются догадками. Отсутствующее отчество допускается только при согласии с MRZ.

4. Проверяются формат серии/номера, существование кода подразделения в исходном справочнике DaData и календарные ограничения. Название органа не подменяется по коду: один код может иметь несколько исторических наименований, отличающихся от разметки. Справочник и атрибуция CC BY-SA 4.0 сохранены без изменений.

5. Даты должны существовать в календаре; паспорт не может быть выдан в будущем или до 14-летия. Срок действия проверяется на 01.10.2026 с учётом замен в 20/45 лет и 90-дневного переходного срока. Утрату, отзыв, смерть владельца и замену документа без доступа к реестрам определить нельзя. Здесь проверяется только календарная действительность.

6. Область автоматического принятия ограничена источником mobile. На web наблюдались согласованные ошибки двух зон, на mobile_v2 - ошибки при завышенной уверенности. Эти источники направляются на пересъёмку/перепроверку. Ограничение источника - консервативная политика по наблюдениям, а не доказательство отсутствия ошибок у mobile.

## 3. Проверка и результаты

Первоначальное разбиение: 2000 development и 1000 holdout, случайная перестановка с seed=20261001. Список идентификаторов сохранён в split.json. После неудачной первоначальной проверки правила были усилены, поэтому прежний holdout уже использован при переработке. Ниже приведена повторная проверка, которую нельзя считать новой независимой валидацией.

| Выборка | Всего | Принято | С ошибкой в полях | Доля принятых |
|---|---:|---:|---:|---:|
| Development | 2000 | 30 | 0 | 1,50% |
| Прежний holdout, повторно | 1000 | 15 | 0 | 1,50% |
| Весь train | 3000 | 45 | 0 | 1,50% |
| Test | 2000 | 45 | неизвестно | 2,25% |

Исходный evaluate.py подтверждает: 45 принятых верно, 0 принятых с ошибкой. Проверка календарной действительности по значениям разметки также даёт 0 недействительных среди принятых. validate.py завершится с ошибкой при любом ошибочном принятии или календарно недействительном принятом документе на размеченных данных.

Выполнены 19 модульных тестов: известные примеры контрольных цифр, расположение цифры серии, повреждение MRZ, несовпадение зон, потеря строк, отсутствие отчества, границы срока действия, низкая уверенность в числовом поле, низкая/отсутствующая/некорректная уверенность MRZ и включительная граница 0,99. Проверена схема ответов, уникальность всех 2000 doc_id и сохранение порядка.

## 4. Что выяснилось и почему пришлось сократить покрытие

Первый вариант проверял уверенность только у части визуальных полей и полагался на совпадение остальных полей с MRZ. Он принимал 307 test-документов, но на 1000 отложенных примерах допустил 2 ошибочных принятия. Это противоречило приоритету задания; такой результат не оставлен итоговым.

Совпадение зон не означает независимого подтверждения: одинаковая ошибка может присутствовать в обеих. Полное применение порога 0,99 отсеивает прежние ошибочные принятия. Вариант с разрешённым web при том же пороге также показал ошибку на повторной проверке, поэтому расширение источников не принято. Списки конкретных ошибочных doc_id, подстановка разметки и запоминание персональных значений не используются.

Политика сознательно предпочитает отказ сомнительному принятию. Увеличение покрытия не считается улучшением, если на доступной проверке появляются дорогие ошибки. При этом 2,25% покрытия - достигнутый результат, а не доказанный максимум: для безопасного расширения нужны новые данные и независимая проверка.

## 5. Прогноз и ограничения

**Прогноз: 45 принятых, 0 ошибочных на test.** Его основание - нулевая наблюдаемая частота ошибок у принятой группы на размеченных данных. Однако 45 принятых примеров мало, а данные уже использовались при выборе правил. Поэтому наблюдаемый ноль не доказывает нулевой риск; корректную независимую доверительную гарантию по этой повторной проверке дать нельзя. Фактическое число ошибок на test будет известно только после сверки с закрытой разметкой.

Для дальнейшего развития нужны свежая отложенная выборка, отдельная калибровка по источникам и независимая перепроверка изображения для сомнительных полей. До такой проверки расширять автоматическое принятие не следует. Остальные документы возвращаются как reject.

## Воспроизводимость и источники

Запуск: python postprocess.py data/test_predictions.jsonl answers.jsonl. Оценка: python validate.py; исходная сверка: python evaluate.py results/train_answers.jsonl data/train_labels.jsonl. Полные метрики и причины отказов находятся в metrics.json и results/.

- MRZ: приказ МВД № 773, приложение 24, https://pvsmvd.ru/media/decrees/060/ec2a3b45.pdf
- Срок действия: постановление Правительства РФ № 2267, пункт 24, https://www.garant.ru/products/ipo/prime/doc/408223437/
